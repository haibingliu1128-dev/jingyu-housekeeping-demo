# 净屿家政 · 在线预约（全栈演示）

> **示例门店**：店铺名称、地址、电话、顾客与评价均为虚构的演示数据（界面标注「示例」），手机号打码显示。短信验证码与支付走**模拟通道**，不会发送真实短信、不会真实扣款。

一个可以直接部署到 Render 免费实例的预约系统：顾客端（手机网页）+ 商家后台，同一个 Node 服务提供 API 与静态页面，数据存 SQLite。
与「栖柚美甲」演示共用同一套内核（预约引擎、防占号规则、评价反馈、店员权限、操作日志、实时推送），本仓库在内核之上实现了 **家政保洁 / 上门服务** 行业的专属流程。

## 演示账号

| 角色 | 用户名 | 密码 | 说明 |
|---|---|---|---|
| 店主 | `owner` | `jingyu2026` | 全部权限（可用环境变量 `DEMO_OWNER_PASSWORD` 覆盖首次创建的密码） |
| 店员 | `staff` | `staff2026` | 派单员小屿（演示）；默认只开「处理预约」 |
| 店员 | `staff2` | `staff2026` | 客服小净（演示）；默认只开「处理预约」 |

顾客端：任意 11 位手机号 → 「获取验证码」→ 演示环境直接在页面显示 6 位验证码。商家后台入口：首页「商家后台」或访问 `/#merchant`。

## 行业功能

- **在线算价（按小时 / 按面积 / 按台数）**：日常保洁 ¥50/小时·3 小时起，深度保洁 ¥8/㎡、开荒保洁 ¥12/㎡（60㎡起算），家电清洗 空调 ¥120 / 油烟机 ¥180 / 洗衣机 ¥150 每台；填写数量即时显示价格明细，下单时以服务端计价为准（明细写入订单）。
- **无电梯搬运费**：填写楼层与是否有电梯，无电梯且 4 层及以上按「(楼层 − 3) × ¥10」自动加收，规则在下单页提前说明。
- **上门时间窗**：只有「上午 09:00–12:00 / 下午 14:00–18:00」两个时间窗，按空闲保洁师人数（4 位）放号，约满显示「已约」；当天时间窗需提前 2 小时预约；数据库触发器兜底防超卖。
- **上门地址**：服务地址 / 楼层 / 电梯，下次下单自动带出常用地址（浏览器本地保存）。
- **门店派单**：派单台列出待确认 / 待派单订单，选择保洁师时「技能不符」或「该时段已有订单」的保洁师自动置灰（服务端同样拦截），支持改派；首页「保洁师档期」表显示今明两天上午 / 下午占用。
- **上门进度 + 顾客验收**：已派单 → 服务中 → 待验收（短信通知顾客，模拟通道）→ 顾客在「我的订单」验收并打分（星级 + 标签），门店不能代替顾客验收；已派单后顾客需联系门店取消；已派单订单不自动记爽约。
- **保洁师评分**：评分记在保洁师名下，首页保洁师列表显示星级与评分次数，保洁师详情页展示简介、擅长项目、评价标签与最近评价。
- **价格设置**：店主在后台修改单价 / 起步时长 / 起算面积 / 每台价格 / 搬运费，保存后顾客端立即按新价计算，已下单订单金额不变；店员需店主授权「管理服务与图片」。

## 快速开始

```bash
npm ci
npm start            # http://localhost:3000 ，首次启动自动建表并写入示例数据（data/housekeeping.db）
npm test             # API 测试（内核通用测试 + 行业测试，临时数据库）
npm run e2e          # 浏览器端到端测试（需要 Python Playwright + Chrome；PY=python 路径可覆盖）
```

## 部署到 Render（免费 Web Service）

仓库根目录已有 `render.yaml`（Blueprint）。在 Render 选择 **New → Blueprint** 指向本仓库即可；或手动 **New → Web Service**，填写：

| 设置 | 值 |
|---|---|
| Name | `jingyu-housekeeping-demo` |
| Runtime / Plan | Node / Free |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| 环境变量 | `NODE_VERSION=20`，`NODE_ENV=production`，`TZ=Asia/Shanghai`，`DB_FILE=./data/housekeeping.db`，`APP_SECRET`（随机生成），`SMS_PROVIDER=mock`，`PAY_PROVIDER=mock`，`DEV_SHOW_SMS_CODE=1`，`DEMO_MODE=1`，`SMS_PER_IP_HOUR=20`，`DEMO_NOTICE=演示环境，数据为示例，每次重启会重置`，`LOG_LEVEL=info` |

免费实例没有持久磁盘：重启 / 重新部署 / 休眠唤醒后 SQLite 文件会丢失，启动时自动重建示例数据（页面顶部有提示条）。`DEMO_MODE=1` 时店主可在后台「重置演示」。

## 架构

```
src/
  server.js / app.js     Fastify 5 启动、依赖装配
  config.js              环境变量
  db/                    SQLite（better-sqlite3）+ 迁移脚本；数据库触发器兜底防超卖（同一时段/人员/课程容量）
  repo/                  数据访问层（sqlite.js 内核表，ext.js 行业扩展表：人员、档案、加购、会员卡、课程、候补）
  services/              booking（事务内下单、状态机、定时任务）、rules（防占号规则）、ext（人员/会员卡/课程/排队/进度）、
                         reviews（评价与反馈）、perms（店员权限）、merchant、auth、images
  industry/index.js      ★ 行业模块：品牌、服务与计价、档案、流程步骤、看板、示例数据
  providers/             短信 / 支付（mock；接口已预留微信支付）
public/
  app.js + style.css     内核前端（顾客端 + 商家后台）
  industry.js/.css       ★ 行业前端：首页、预约步骤、订单展示、商家扩展页、主题色
test/
  core.test.js           内核通用 API 测试（通过 test/fixture.js 适配本行业）
  industry.test.js       行业 API 测试
  e2e.py                 Playwright 端到端测试
```

- **下单在一个 SQLite 事务里完成**：校验规则 → 计价 → 检查容量/人员冲突 → 写入；另有数据库触发器在多进程并发时兜底。
- **防占号规则**（商家后台可开关/调整，立即生效）：未完成预约上限、每天/每周上限、取消时限与每月取消次数、频繁预约取消暂停、超时未到自动记爽约、爽约 N 次后限制或要求定金、新客需确认、黑名单。
- **评价与反馈**：仅本人已完成的订单可评价、期限内可改、低分实时提醒、商家回复/隐藏/先审后发；意见反馈仅商家可见。功能开关仅店主可改。
- **店员权限（9 项）**：处理预约（默认开）、拉黑/解除拉黑、查看完整手机号、回复/隐藏/审核评价、处理反馈、管理服务与图片、修改防占号规则。未授权时所有接口在**服务端**打码手机号；权限变更通过 SSE 即时生效。行业操作（进度推进、派单、核销、叫号等）归入「处理预约」，价格/排班/课程归入「管理服务与图片」。
- **实时**：商家端与顾客端通过 SSE 自动刷新（新预约、状态变化、改价、排班等），公开推送不含顾客数据。
- **操作日志**：登录、预约处理、规则修改、权限变更、短信通知等均有记录（仅店主可看）。
- **始终浅色显示**：`color-scheme: light only`，不跟随系统深色模式。

## 上线前还需要什么

真实短信通道（阿里云/腾讯云）、真实支付（微信支付商户号与回调域名）、持久化存储（云服务器磁盘或付费磁盘，并配置 `scripts/backup.sh` 定时备份）、修改所有演示密码与 `APP_SECRET`、替换示例门店信息与图片、隐私政策与用户协议。

## 已知限制

- 免费实例休眠后首次访问需等待约 30–60 秒唤醒；数据会重置（见上文）。
- 单实例 SQLite，适合单门店；多门店/多实例需迁移到 MySQL/PostgreSQL（repo 层已隔离 SQL）。
